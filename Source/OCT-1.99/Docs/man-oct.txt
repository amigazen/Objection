 Name     Name

     oct - Invokes Object Oriented C Translator 


 Syntax     Syntax

     oct [options].. method_file      oct


 Description     Description

     ___  is  an  Objective C Translator translator.  It provides     oct
     Smalltalk-like  message  expressions  to the "C" programmer.
     The  system  does  not  provide binary operator overloading,
     ala  Ada  and  C++.  However, since the operators are named,
     these  methods are also overloadable.  It accepts a superset
     of  "C" and outputs "C" code acceptable to __ which the user                                                cc
     must  invoke.   The  translator  uses interface header files
     for references generated by message expressions.  

     The  input  filename  is  an  Objective  C Translator source
     language  file.   The  source file must have an extension of
     .m   .    The  input  file  must  include  the  header  file     .m
     <objc/objc.h>  (or  an  @includes()  directive)  sothat  the     <objc/objc.h>
     translated  .c  file  can  be  compiled  correctly.   If the                 .c
     translator  approves of the syntax in the .m file, then a .c                                               .m              .c
     file  will  be produced.  If a file translates successfully,
     __  may  still complain of errors.  Lines numbers will refer     cc
     back  to  the  original  .m  file.   The  user invokes the C                              .m
     compiler manually.  
       The translator  should  be  used  on  files defining a new
     class,  and  on  files containing message expressions.  Both
     types  of  files  are  outlined  below.  The file containing
     main()   must   be  translated,  as  main()  is  changed  to
     appl_main()  so  the  Objective C Translator runtime package
     can  get  a  chance  to  initialize  itself.  The translator
     allows  definition of classes with extend the known types of
     the  base  system.  Single inheritence from another class is
     provided.   An  additonal comment style like BCPL and C++ of
     "//"  indicating  that  text  upto  the end of the line is a
     comment   is   added.   Additional  preprocessor  directives
     introduced with "@" are also added.

     These options are available, 

     -l      -l
           Produce  a  .lst  file describing the methods defined,                       .lst
           messages  that  don't  have a known return type, class
           variables,  and  other  useful  information that other
           tools  can  use  to  update  class  information  files
           (datasets).   Useful  in combination with -n option if                                                     -n
           you're updating the local dataset file.                                       dataset

     -n      -n
           Suppress   generation  of  the  output  file  (ie,  no
           output).    Useful  when  just  gathering  information
           about  a  class,  or  to test if a file will translate
           successfully.  

     -o outputfile      -o
           Specify  an  output file.  Normally a ".c" is appended
           to the input base pathname.  

     -i includedir      -i
           Specify  additional  include  directories  to have ___                                                              oct
           cpp   search.   Normally  you'd  use  the  environment
           variables.  

     -p pre_proc_flags      -p
           Allows  user to pass flags and such to ____  Useful to                                                  cpp.
           send   small/large  data  model  settings  that  would
           normally  be  defined  by the compiler.  But since the
           compiler  isn't  invoking  ___  these  symbols  aren't                                      cpp
           known  at  this  time.  This parameter may be repeated
           many times.  

     -w#      -w#
           Sets  the  warning  level for the translator.  Level 0

     -za      -za

     -zk      -zk

           Pipe  the  output file to stdout instead of creating a

     The  following  directives  are  available  in  the .m file.                                                         .m
     There  must be __ whitespace between the at-sign (@) and the                    no
     directive.  

     @defs (classname)      @defs
           Inserts  the  class  instance  variables into the text
           stream.   A  trailing  semicolon  (;) is inserted into
           the text.  Example, @defs(Sequence).  

     @end      @end
           Offically mark the end of a class definition.  

     @implementation classname:superclass{vars}      @implementation
           Defines  the  class for this input file.  'superclass'
           is   optional,   as   is   the   instance's   variable
           declaration.  

     @includes ()      @includes
           If  a  file  without  any  class  definitions is being
           translated,  then this directive must follow the files
           #include  directives.   After  the text is translated,
           ___   needs   to  include  <objc/objc.h>  again.   The           oct                        <objc/objc.h>
           include  statement  is  normally triggered off a class
           definition,  but if the file includes none, it must be
           done manually.  See below for example use.  

     @selector (method)      @selector
           Substitutes  the internal method selector code for the
           text  name.   Currently,  the  implementation converts
           the  code and compile time; therefore, the method name
           must be a constant.  Example, @selector(at:put:).

 Example     Example

     Here  is  an example of two files, one defining a new class,
     and  the  other  a  main()  routine  that references the new
     class.  

     The file main.m contains a reference to the class:               main.m

     //  main.m     Demonstration main program.

     #include  <objc/NewBytes.h>
     @includes()
     //  Since we don't define a class here,
     //  @includes() trails our includes

     main()
     {
        id   nb;

        nb = [NewBytes str:"!dlrow olleH"];
        [nb reverse];
        printf( "%s\n", [nb str] );
        [nb free];                  //  <-- rather important
     }  /* main */


     The  file  newbytes.m  contains  a  class  the  extends  the                newbytes.m
     foundation  class   ByteArray  with one new method, reverse,                         ByteArray
     which   calls   a   library  routine  to  reverse  a  string
     in-place.  

     //  NewBytes    Demonstration class

     #ifndef _NEWBYTES_H
     #define  _NEWBYTES_H  1

     #include  <objc/NewBytes.h>

     @implementation  NewBytes : ByteArray

     - reverse
     {
        strreverse( IV(self) );   // Access the string array
        return self;
     }
     @end
     #endif


     Although  the  new  class  is  unknown  to  the  system, the
     superclass  is  known, so instance variables can be located.
     To  translate,  compile, and link this sample, the following

     commands  (or at least similar ones) could be issued.  First
     an   interface   file  is  created  declaring  the  instance
     variables  and  return  return type for 'reverse'.  Then the
     two  .m  files  are  translated and compiled.  The prelinker          .m
     creates  a  file  containing a list of classes needed to run
     this  application,  and  that list is compiled.  Finally the
     three  object  files  are linked with the system classes and
     the standard libraries.  

     >>> oct -w2 main.m
     (OCT 1.85 Translator)
     Note: no classes defined in this file.
     >>> cc main.c
     >>> oct newbytes.m
     (OCT 1.85 Translator)
     >>> cc newbytes.c
     >>> prelink ww.c main.m newbytes.m
     (prelink 1.04)
     >>> cc ww.c
     >>> ln -o main main.o newbytes.o ww.o -looc:include/ocbase -lc
     >>> main
     Hello world!

 Diagnostics     Diagnostics

     If  the  translator  gets  hung  up on an expression it will
     usually  abort.   A  message of cause is printed, but it may
     not  mean  much.  The message "flex input buffer overflowed"
     may  be  related to strings in the file.  Check the C output
     file for the last token the translator was able to read.  

     "method  is  generic"  means that no description of a method
     selector  was  found  in  the  method  interface  definition
     files.   This  warning  isn't  fatal;  it just means that no
     type  casting  of  the  return value will be performed.  The
     compiler  will probably also complain if the return value is
     assigned to a non-id type variable.  

     If  there  is a type disagreement between any interface file
     and  a  method  call,  either  the warnings "mismatch return
     type"  or  "mismatch  parameter  type"  will  be  displayed.
     Currently,  the storeage class of each parameter must match;
     this  should be relaxed in the future.  Fatal errors include
     unable  to  system()  ____   If  the preprocessor returns an                           cpp.
     error value, then translation stops.
